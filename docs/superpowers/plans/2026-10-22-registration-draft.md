# 报名草稿实施计划

目标：用户手动保存任意完成程度的报名内容，下次进入直接恢复，并可清除草稿。

方案：沿用 `index.html` 的原生表单和中英文消息机制，使用按大会命名的 localStorage 键保存白名单字段、身份和套餐编号、填写步骤、VIP 输入值及保存时间，7 天过期。图片、隐私同意、公开展示授权、价格及 VIP 校验结果不保存。

执行范围：当前会话内完成，按用户明确授权提交 Git，不推送。

1. 在 `test/registration-draft.test.js` 添加行为测试，覆盖部分填写、恢复、过期、损坏、存储异常、清除及提交结果，运行并确认新增功能尚未实现。
2. 在 `index.html` 添加次要按钮“暂存草稿”和“清除草稿”；草稿操作不显示提示弹窗。保存成功后按钮显示“✓ 已暂存”1.5 秒，失败时在按钮下方显示小号“暂存失败，请重试”。
3. 添加白名单序列化和恢复逻辑；首次打开报名弹窗直接恢复，套餐从最新接口匹配；VIP 不自动恢复有效状态。后续关闭重开保留当前内存内容，避免旧草稿覆盖新编辑。
4. 清除时先删除本地草稿，成功后重置当前表单；提交成功删除草稿，失败保留。提交期间禁用草稿操作以避免状态竞争。
5. 运行草稿、报名客户端、报名数据及相关资料单元测试；执行 `git diff --check` 并审查差异。不运行浏览器验证。

执行结果：以上步骤已完成。移除所有草稿提示浮层，保存反馈融入按钮，失败反馈使用按钮下方小字。恢复与清除保持无弹窗；重复保存重新计时，清除时重置反馈。草稿、报名客户端、报名数据、资料客户端及订单流程共 55 项单元测试通过；`git diff --check` 通过。未执行浏览器验证或 Git 推送。
