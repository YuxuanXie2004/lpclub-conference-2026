# 展示柜手动上传实现计划

目标：管理员在嘉宾肖像和机构标识分类中上传独立素材，加入当前展示草稿，保存后才发布。

实现沿用 Node.js、MySQL、私有文件存储及现有展示柜草稿。新增独立素材表，不创建报名记录，不修改报名素材的审核或授权规则。

- [x] 先补针对性测试：独立素材加入草稿、受保护上传与预览、上传不发布、混合排序、保存及移除、旧版本冲突和非法图片。
- [x] 新增 `003-manual-showcase.sql`；在 `server/showcase.js` 接入上传、预览、展示柜事务保存；复用图片解码和原件存储。
- [x] 在 `server/materials.js` 合并已发布独立素材，公开图片仍逐次检查发布状态。
- [x] 在 `assets/showcase-admin.js` 的分类工具栏加入上传按钮和文件选择器；上传后加入草稿，复用文字、裁剪、排序和移除。补充中英文文案及资源版本。
- [x] 执行相关 Node 测试及可用的隔离 MySQL 测试，检查差异；不执行浏览器验证、提交或推送。

边界：仅静态 JPG/PNG/WebP，最大 5 MiB、2500 万像素；上传与保存失败保留已有草稿；手动肖像发布须填写姓名，机构标识须填写机构名。手动上传直接加入右侧展示草稿，不进入资料候选区；移出保留原件，如需再次展示请重新上传。每类展示柜仍使用同一修订号及完整列表事务，避免部分发布。

验证结果：相关客户端、HTTP、资料、裁剪、缓存、MySQL 展示柜与迁移测试全部通过。新增迁移已应用于本地数据库，健康检查返回 `003-manual-showcase.sql`，后台页面已引用新的脚本版本。JavaScript 语法检查和 `git diff --check` 通过；未进行浏览器验证，未提交或推送。
